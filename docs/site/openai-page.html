What a run looks like

You type (ChatGPT form; in Codex start with $pressure-design):

Use the pressure design skill. B31.3-2022, normal fluid service. NPS 6 seamless pipe, OD 6.625 in,
design 750 psig at 600 F, corrosion allowance 0.0625 in, 12.5% mill tolerance. My allowable S at
600 F is 17900 psi from my copy, E = 1.0, W = 1.0, Y = 0.4. What minimum thickness do I need and
does 0.280 in nominal wall work?

The skill writes the inputs to a job file, runs pressure_design.py, and reports from the script output:

QuantityValueBasis
Pressure design thickness t0.1365 inB31.3-2022 ¶304.1.2 Eq. (3a): PD / 2(SEW + PY)
Minimum required tm0.1990 int + c, c = 0.0625 in
Nominal wall to order0.2274 intm / (1 − 0.125), 12.5 % mill tolerance
Allowable pressure at 0.280 in nominal1,008 psigSame equation solved for P on 0.280 × 0.875 − c

Verdict: PASS 0.280 in nominal works, with 0.053 in of wall and about 34 % of pressure margin. S, E, W and Y are echoed as user-supplied. The calc sheet names the edition, the equation, every input and anything you left to be ASSUMED, then lists what a reviewer would flag: the Table A-1 line behind S, the Table A-1A line behind E, the Table 304.1.1 row behind Y, the purchase spec behind the mill tolerance.

With the optional connector on and a plan that covers the table, S, E, W and Y can instead arrive from lookups. The calc sheet then shows each one with its citation and a source column that reads connector instead of user; the script's arithmetic is the same.

What it does

PipingToolset is a plugin: seven skills, each a set of written instructions the assistant follows plus a standard-library Python script that performs the calculation. The assistant asks for the code basis and the inputs, writes a small specification file, runs the script by path, and reads the result back to you. The scripts reproduce the locked fixture cases of the calculation engine behind the free calculators on this site.

How it works

1 · You describeThe line, the code and edition, the service, the inputs you have read from your copy of the code.
2 · The assistant interviewsAnything missing is asked for. Anything you leave open is written down as ASSUMED.
3 · A script computesStandard-library Python, called by path, no network. The assistant never does the arithmetic.
4 · You read the tableEdition, equation, inputs and where each code-table value came from, result, verdict, warnings. Output files land in your working folder.

Three rules hold in every skill:

  • The assistant never does the arithmetic. Every number a skill states comes from a script run on inputs you supplied or looked up. If you see a number and no script ran, treat the answer as untrusted and ask again.
  • The assistant never quotes a code table value from memory. Allowable stresses, moduli, SIFs, spans, ASCE 7 coefficients, anchor bond values, flange ratings, gasket factors: the skill names the table, row and edition, and the value comes from one of two places. Either you read it from your own copy, or, with the optional connector and a plan that covers the table, a lookup returns it with its citation. Asking for "just the number" with the connector off is a pinned test, and the answer is no.
  • The edition is an input, never a silent default. Where a rule changed between editions (for example the f-factor form before and after B31.3-2022, or Appendix D giving way to B31J from B31.3-2020), the skill asks which one governs your project.

Optional: the Engineering Data connector

The plugin is free and every skill works without this. The connector is a separate, optional remote server (pipingtoolset-data at https://pipingtoolset.com/mcp) that ChatGPT or Codex can call for a table lookup. When it is on, the assistant asks for one value at a time and passes each answer to the script as a cited input marked connector-supplied. The calc sheet shows the source of every code-table value, user or connector. A script still does all the arithmetic, and you still verify each value against your own copy and edition before anything is issued.

What a lookup returns

One envelope per value: the value and its unit, the column, a citation (standard, edition, table, row, column and any table notes), whether it was served or is a pointer, the tier it needed, the dataset id and version with a hash of the rows used, and, when it interpolated, the tabulated entries it interpolated between. A pointer returns the same fields with the value empty. A signed-in request your plan does not cover returns one line naming the plan it needs and the pricing page.

lookup_value dataset_id: b313-allowable-stresses-2024 key: { spec: A106, grade: B, T: 650 } column: S

The edition in the citation is the edition that was read: check it against your project's edition basis.

What is sent

Only lookup keys: the standard, the material or table row, a temperature, a size. Not your inputs, loads, drawings, prompts or results. Connecting contacts pipingtoolset.com; disconnect the server in your host and nothing is sent there. Sign-in goes through pipingtoolset.com, handled by your host, and asks you to confirm that your OpenAI account is set not to train on your conversations.

Add or remove it

  • Codex. codex mcp add pipingtoolset-data --url https://pipingtoolset.com/mcp, then codex mcp login pipingtoolset-data when a lookup needs your plan. The plugin's mcp.json declares the same server for hosts that read it.
  • ChatGPT. Turn on developer mode in the connector settings, create a connector with the MCP server URL https://pipingtoolset.com/mcp and OAuth authentication, and sign in through pipingtoolset.com when asked.

To turn it off, disconnect or disable pipingtoolset-data in the host's connector or MCP settings. The skills then ask you to read each table value from your own copy, exactly as before.

What it will not do

  • It will not hand you a tabulated code value from its own files. The plugin contains no allowable stress, quality factor, Y coefficient, SIF, support span, catalog bond strength, B16.5 rating, gasket factor or API nozzle allowable. You read the value from your copy of the document, or the optional connector serves it with a citation. For the tables the connector currently serves as pointers (API nozzle allowables, PVP2011-57100, ASCE 7-22, AISC and ACI tables, NEMA SM-23) it returns where the value is printed and never the value, and for B31J it returns the component row text, not the SIF.
  • It will not replace a flexibility analysis. Stress screening is a hand check of what the program applied. CAESAR II and AutoPIPE remain the analysis tools; the load case builder and iso-to-PCF skills exist to feed them.
  • It will not pick your code or edition for you. Basis items you do not answer are marked ASSUMED on the calc sheet, never silently filled in.
  • It will not compute in the model's head. A skill that cannot run its script, for example in a chat surface with no sandbox, stops and says so instead of estimating.
  • It will not seal anything. Results are engineering aids. A looked-up value is still yours to verify against your own copy and edition. The engineer of record verifies the result before issue, and you remain responsible for it.
  • It will not reproduce code text. Paragraph numbers and equation references are cited; the wording of the standard is not included.
  • It will not require an account. The plugin is free and works as written without the connector. Currently the connector's code-table lookups need a signed-in Pro, Pro Plus or Ultimate account at the tier that covers the table; the skills never do, and a subscription changes nothing in the plugin.

Where your data goes

Short answer: the skills and their scripts make no network calls, carry no telemetry and need no account with us. The one optional connection is the Engineering Data connector above. With it off, the only contact with our infrastructure is the download, which GitHub serves. With it on, the assistant sends lookup keys and nothing else.

Install

In the ChatGPT desktop app and Codex

  1. With the Codex CLI installed, register the marketplace once:
    codex plugin marketplace add pipingtoolset/pipingtoolset-claude
  2. Install PipingToolset from the plugin picker: /plugins in the Codex CLI or IDE extension, or Customize › Plugins in the ChatGPT desktop app. It shows with the PipingToolset mark and "By Flexible Piping Solutions LLC"; the seven skills are listed beneath it.
  3. Start a new conversation. Call a skill as $pressure-design (or pick it from /skills) in Codex, or name it in plain words in ChatGPT: "use the pipe support skill to check PS-201". Naming it matters, because other installed skills on the same topics would otherwise compete.

To update, run codex plugin marketplace upgrade pipingtoolset and reinstall from the picker.

Skills only, for other assistants

The skills are plain Agent Skills, so the same repository installs into Cursor, GitHub Copilot, Gemini CLI and others with npx skills add pipingtoolset/pipingtoolset-claude or gh skill install pipingtoolset/pipingtoolset-claude. Those routes carry the skills and scripts only; add the connector by hand if you want it. For Claude Code and Claude Cowork, see the Claude page.

PipingToolset is not in the ChatGPT plugin directory; the routes above are the installs.

The connector

The plugin's mcp.json declares the Engineering Data connector for hosts that read it; you choose whether to connect it. Setup lines for each host are in the connector section.

Requirements

Python 3.9 or newer wherever the scripts run: your own machine for the Codex CLI and IDE extension; the ChatGPT desktop app and Codex cloud provide their own sandbox. There is nothing else to install. The connector needs no software on your side.

Check that against your own copy. More prompts with pass criteria are in the repository's test prompt set.

How it is verified

  • One calculation engine. Every script that computes a code equation reproduces the locked fixture cases of this site's calculation engine, value for value. A red parity test blocks a release. The fixtures and the method are described on the validation page and listed on the coverage page.
  • Scripts stay offline. A test fails the build if any script under the skills imports a network module. The connector is the only network path, and the scripts only receive its answers as a cited code_values input; one that disagrees with a value you typed stops the run.
  • Cited, versioned values. Every served value carries its standard, edition, table and row, the dataset version and a hash of the rows used, and the calc sheet shows whether you or the connector supplied it.
  • Same refusals without the connector. The refusal prompts give the same answer with the connector off, and the skills fall back to the interview on a pointer, an account or limit message, or any error.
  • One archive. The .zip for upload dialogs is byte for byte the .plugin Cowork installs, and the agentskills.io reference validator passes every skill folder in CI.
  • Golden outputs. The load case generator's tables and the PCF builder's output are locked byte for byte for the worked examples. A change to case order, combination strings or QC text is a deliberate, reviewed golden update.
  • Content guard. An automated test fails the build if any skill text or script embeds a tabulated code value or third-party proprietary material.
  • Recall channel. An installed copy keeps any defect it shipped with until you update it. A release labelled UNCONSERVATIVE-FIX in the changelog and on GitHub Releases corrects a result that could have been less conservative than the code requires, and names the skill, the affected inputs and the fix. Update when you see one.

Questions

Do I still need my own copy of the code?

Yes. With the connector off, you read every table value from it. With the connector on, a served value arrives cited, but you still verify it against your copy and edition before issue, and the pointer-only tables always need your copy.

Which codes and editions?

ASME B31.3 and B31.1 for pressure design, screening and load cases, with the edition as an explicit input wherever a rule differs between editions. Pipe support checks use ASCE 7-22, AISC 360-22, ACI 318-19 Chapter 17 and AWS D1.1. Nozzle loads follow API 610, 617 / 611 / 612, NEMA SM-23, API 660 / 661 / 560, API 650 Annex P and ASME PVP2011-57100. Flange checks follow ASME B16.5 and BPVC Section VIII Division 2 Part 4.16. The iso-to-PCF skill targets the CAESAR II PCF import.

Does the connector see my project?

No. It receives lookup keys only: the standard, the material or table row, a temperature, a size. Your inputs, loads, drawings and results stay in your session and your working folder. Disconnect it and nothing is sent to pipingtoolset.com.

What does the connector cost?

The open tools need no account. Currently the code-table lookups need a signed-in paid pipingtoolset.com account (Pro, Pro Plus or Ultimate) at the tier that covers the table; the tiers and the tables they cover are on the pricing page and the connector page and can change. A signed-in request your plan does not cover returns one line naming the plan it needs.

Does it work in ChatGPT on the web or on my phone?

The tested routes are the ChatGPT desktop app and Codex. A surface that cannot run the bundled Python stops at the interview and says so.

Is it the same plugin as the Claude one?

Yes, the same folder and the same release. It carries a Claude manifest and an Agent Plugins manifest side by side, and the skill text names no single assistant, so a calc sheet from ChatGPT and one from Claude cite the same paragraphs and show the same numbers for the same inputs.

How much does it cost?

The plugin costs nothing. It is free and open source under the Apache License 2.0, and you pay only for your own OpenAI plan. The optional connector is described above.

How do I report a wrong result?

Open an issue in the GitHub repository with the prompt, the script command that ran and the line you dispute, or write to support@pipingtoolset.com. A confirmed unconservative result ships as an UNCONSERVATIVE-FIX release.
